# HeartSignal 비즈니스 모델

> 작성일: 2026-10-26 · 관련 문서: [기획서](HeartSignal-Plan.md), [명세서](HeartSignal-Spec.md)
>
> 이 문서는 팀 논의용 초안입니다. 법령 조항·지원사업 내용은 ⚠️ 표시한 부분을 원문으로 확인한 뒤 확정합니다.

## 1. 핵심 전제 — 구매자와 사용자가 다르다

| 구분 | 누구 | 관심사 |
| --- | --- | --- |
| **사용자** | 작업반장(`foreman`), 작업자(`worker`), 안전관리자(`admin`) | 비상시 손이 덜 가는가, 안내가 정확한가 |
| **구매 결정자** | 안전환경팀장, CSO, 경영책임자 | 법적 의무를 이행했다는 **증거가 남는가**, 사고 대응 시간이 줄어드는가 |

구매 결정자는 "현장이 편해진다"보다 **"대응 시간을 줄이고, 그 대응을 했다는 증거를 자동으로 남긴다"** 에 비용을 지불합니다. 이 문장이 HeartSignal의 핵심 판매 메시지입니다.

## 2. 이해관계자별 구매 이유

| 이해관계자 | 구매 동기 | HeartSignal이 주는 근거 |
| --- | --- | --- |
| **경영책임자 (대표·CSO)** | 중대재해처벌법상 급박한 위험에 대비한 작업중지·대피 매뉴얼 마련과 반기 1회 이상 점검 의무 (시행령 제4조) ⚠️. 사고 시 이행 여부를 증명해야 함 | 경보·도구 실행마다 감사 로그(누가·무엇을·결과), 사람이 발령·해제하는 구조로 책임 소재가 분명 |
| **안전환경팀** | 화학물질관리법상 화학사고 즉시 신고 의무 (시행규칙상 15분 이내로 파악, 확인 필요) ⚠️. PSM 비상조치계획의 실효성 입증 | 119 신고문 자동 정리(물질·UN번호·CAS·초기이격거리), 경보→신고 소요 시간 측정 |
| **현장 조직 (반장·작업자)** | 비상시 대피 지휘·연락·문서 확인이 동시에 몰림, 협력사·신입 인력의 교육 편차 | 근거가 붙은 체크리스트, 출처가 표시된 전광판 안내, 작업 전 질의 챗봇 |
| **원청·보험사** (간접) | 협력사 안전관리 수준 평가, 위험 평가 | 훈련·대응 기록 리포트 |

## 3. 필수 비즈니스 모델 요소

### 3.1 평상시 사용 기능 — 갱신률을 지키는 장치

비상 경보는 연간 발생 횟수가 적습니다. 평소에 쓰이지 않는 제품은 계약 갱신 시점에 해지됩니다.

- **훈련(Drill) 모드**: 실제 경보와 같은 흐름을 훈련용으로 실행하고 결과 리포트를 자동 생성. 중대재해처벌법의 반기 점검 의무 이행 증빙으로 활용
- **작업 전 질의 (현재 RAG 챗봇)**: 일상 사용 기능. 향후 TBM(작업 전 안전점검 회의)·작업허가서 발행 단계와 연결

### 3.2 수익 구조

| 항목 | 방식 | 비고 |
| --- | --- | --- |
| **라이선스** | 사업장 또는 관리 구역(zone) 수 기준 연간 구독 | 작업자 수 변동이 커서 좌석 기준은 부적합 |
| **구축비** (일회성) | 고객사 비상조치계획·MSDS·PSM 문서 적재, 구역 지도, 전광판·방송 설비 연동 | 초기 매출의 큰 비중 예상 |
| **유지보수·문서 갱신** | KOSHA 지침·법령 개정 반영, 인덱스 재생성 | 반복 매출의 명분 |

### 3.3 요금제

| 등급 | 대상 | 포함 기능 |
| --- | --- | --- |
| **Basic** | 중소 화학공장, 협력사 | 문서 근거 챗봇 + 템플릿 경보 |
| **Standard** | 단일 사업장 | 경보 에이전트, 대시보드, 훈련 모드, 감사 리포트 |
| **Enterprise** | 대형 정유·석유화학 | 설치형 배포, 설비·신고 연동, 맞춤 문서, SLA |

중소 사업장은 예산이 작으므로 **산업단지 단위 공동 도입**이나 **정부 지원사업**(예: 안전보건공단 스마트 안전장비 지원 ⚠️ 대상·요건 확인 필요) 연계 경로를 검토합니다.

### 3.4 설치형(온프레미스) 배포 옵션

정유·석유화학 사업장은 망분리가 일반적이어서 외부 LLM API 호출이 막힐 수 있습니다.

- 온프레미스·프라이빗 클라우드 설치 지원
- 사내 LLM으로 교체 가능한 구조 (현재 `LLM_MODEL` 설정 → 공급자 교체까지 확장)
- **셀링 포인트**: 현재 설계상 LLM이 없어도 경보·방송·신고는 고정 템플릿으로 동작 (AGENTS.md 2장 4번)

### 3.5 책임 범위의 계약 명시

"AI가 대피를 잘못 안내했다"는 분쟁에 대비합니다.

- 판단(경보 발령·해제, 대피 지휘, 설비 조작)은 사람이 하고, 에이전트는 **문서 근거를 정리하는 보조 도구**임을 계약서에 명시
- 현재의 사람-에이전트 역할 분리 원칙(AGENTS.md 2장 1·2번)은 기술 설계이자 **법적 방어 수단**

## 4. 상용화 전 메워야 할 제품 공백

| 우선순위 | 공백 | 현재 상태 | 필요한 것 |
| --- | --- | --- | --- |
| 1 | 경보·감사 기록의 영구 저장 | `RAG/alarm/store.py`의 `_alarms`는 메모리 dict, 감사 로그는 표준 출력 → 재시작 시 기록 소실 | DB 영구 저장, 기간별 대응·훈련 리포트 내보내기 |
| 2 | 성과 지표 | 측정 없음 | 경보→전광판 표시, 경보→신고문 완성 소요 시간을 시연에서 측정해 ROI 근거로 제시 |
| 3 | 훈련 모드 | 없음 | 실제 경보와 구분되는 훈련 경보, 결과 리포트 |
| 4 | 외부 연동 | 119·문자는 모의 발송 (AGENTS.md 2장 5번, 현 단계 규칙) | 상용 단계에서 방송·전광판 장비 업체, 문자 게이트웨이 파트너 |
| 5 | LLM 공급자 교체 | OpenAI 고정 | 사내·프라이빗 LLM 연결 옵션 |

## 5. 요약

HeartSignal의 필수 비즈니스 모델 요소는 세 가지입니다.

1. **평상시 사용** — 훈련 모드와 작업 전 질의로 매일 쓰이게 한다
2. **규제 대응 증거** — 감사 로그와 리포트로 법적 의무 이행을 증명하게 한다
3. **설치형 배포** — 망분리 환경에서도 동작하게 한다
